# BuggyBoard Bug Status (Open/Closed) End-to-End Test Plan

- Version: 0.1
- Generated by Claude for Philip Wong on 24 September 2026
- Reviewed by: Philip Wong on 24 September 2026

## Feature Overview

BuggyBoard tracks a bug's state (Open or Closed). New bugs are created Open; the edit-bug modal lets a user change state; and the board has an Open/Closed filter toggle above the table, which combines with sorting and searching.

## Test Scenarios

### 1. New bugs default to Open

#### 1.1. Creating a bug saves it with state Open and it appears under the Open filter

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. The board's state filter is Open (the default).

**Steps:**

1. Create a new bug with a unique title via the New Bug modal.

**Expected Results:**

1. The new bug appears in the board table while the Open filter is selected. [13-AC1]

### 2. Changing state via the edit-bug modal

#### 2.1. Edit modal displays and allows changing state

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. An Open bug exists with a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug.

**Expected Results:**

1. The State field shows "Open". [13-AC2]

#### 2.2. Changing state to Closed and saving updates the database and board

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. An Open bug exists with a known unique title.
3. The board's state filter is Open.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the State field to "Closed".
3. Click Save.

**Expected Results:**

1. The Save button becomes enabled once the state changes. [13-AC2]
2. After saving, the bug no longer appears in the board table while the Open filter is selected. [13-AC2]
3. Selecting the Closed filter shows the bug. [13-AC2]

### 3. Board state filter defaults and toggling

#### 3.1. Board state filter defaults to Open

**Preconditions:**

1. Authenticate as `buggy`.
2. Both an open bug and a closed bug exist with known unique titles.

**Steps:**

1. Navigate to the board page.

**Expected Results:**

1. The Open filter button is visually selected (active styling). [13-AC3]
2. The board table shows the open bug's title. [13-AC3]
3. The board table does not show the closed bug's title. [13-AC3]

#### 3.2. Selecting Closed shows only closed bugs

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. Both an open bug and a closed bug exist with known unique titles.

**Steps:**

1. Click the Closed filter button.

**Expected Results:**

1. The board table shows the closed bug's title. [13-AC4]
2. The board table does not show the open bug's title. [13-AC4]

### 4. Filter combined with sorting and search

#### 4.1. Sorting applies only within the selected state filter

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. At least two open bugs exist with distinct known titles; at least one closed bug exists with a title that would otherwise sort between them.
3. The board's state filter is Open.

**Steps:**

1. Click the Title column header to sort ascending.

**Expected Results:**

1. Only the open bugs' titles are displayed. [13-AC5]
2. The displayed open bug titles are in ascending order. [13-AC5]

#### 4.2. Search and state filter apply together

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. An open bug and a closed bug exist, both with a shared keyword in their titles (e.g. "Widget"), plus another open bug without the keyword.

**Steps:**

1. Select the Open filter.
2. Enter the shared keyword in the search field.

**Expected Results:**

1. Only the open bug containing the keyword is displayed. [13-AC6]
2. The closed bug (matches search but not state) is not displayed. [13-AC6]
3. The other open bug (matches state but not search) is not displayed. [13-AC6]

### 5. No matches message

#### 5.1. Selecting Closed with no closed bugs shows a no-bugs-matched message

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. All bugs in the database are Open (delete/avoid any Closed bugs).

**Steps:**

1. Click the Closed filter button.

**Expected Results:**

1. The board displays a "No bugs matched." message. [13-AC7]
2. No bug rows are shown in the table. [13-AC7]

## Out of Scope (deferred)

- General column-sort correctness (order per column/direction) is covered in `specs/test-plans/sort-board-columns.md`; this plan only verifies sorting stays scoped to the selected state filter.
- General search correctness (normalization, title-only scope) is covered by the existing `tests/search-bug/*` specs; this plan only verifies search stays scoped to the selected state filter.
- Editing other fields alongside state (title/severity/owner/description) is covered in `specs/test-plans/edit-bug.md`.

## Technical Information

### Seed / Fixture Guidance

Use `tests/seed.spec.ts` as the Playwright seed. Create bugs via `tests/support/board-fixtures.ts` (`createBug`), which already supports `state: "OPEN" | "CLOSED"` and issues a follow-up PUT to close a bug at creation time. Use unique titles per test and clean up with `deleteBugIfExists`/`deleteAllBugs` so a test's state-filter assertions aren't affected by other bugs.

### Locator Guidance

Reuse `tests/pages/board.page.ts`: `openFilterButton` (`getByRole('button', { name: 'Open' })`), `closedFilterButton` (`getByRole('button', { name: 'Closed' })`), `noBugsMatchedMessage`, `rowByTitle`. For the edit modal's State field, use `dialog.getByLabel('State')` with `selectOption('closed')` / `selectOption('open')`, alongside `tests/pages/edit-bug-dialog.page.ts`'s `saveButton`.
