# BuggyBoard Board Severity Color-Coding End-to-End Test Plan

- Version: 0.1
- Generated by Claude for Philip Wong on 24 September 2026
- Reviewed by: Philip Wong on 24 September 2026

## Feature Overview

BuggyBoard's board table color-codes each bug's severity badge (HIGH, MID, LOW) using distinct design-system colors so more critical bugs draw the eye.

## Test Scenarios

### 1. Severity badges are color-coded

#### 1.1. Each severity level renders its own badge styling

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. Bugs exist with known unique titles for severities HIGH, MID, and LOW.

**Steps:**

1. Locate the severity badge for each of the three bugs.

**Expected Results:**

1. The HIGH bug's severity badge has the `severity-badge-high` class and `data-severity="HIGH"`. [08-AC1, 08-AC2]
2. The MID bug's severity badge has the `severity-badge-mid` class and `data-severity="MID"`. [08-AC1]
3. The LOW bug's severity badge has the `severity-badge-low` class and `data-severity="LOW"`. [08-AC1]
4. The three badges each have a different class, i.e. no two severities share the same badge class. [08-AC3]

#### 1.2. Severity badge updates when a bug's severity is edited

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with severity LOW and a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Severity field to HIGH and save.

**Expected Results:**

1. The board row's severity badge now has the `severity-badge-high` class and `data-severity="HIGH"`. [08-AC1]
2. The badge no longer has the `severity-badge-low` class. [08-AC1]

## Out of Scope (deferred)

- Pixel-level or computed-style color-value assertions (e.g. reading `getComputedStyle` for exact hex values `#b84a2e`/`#a67c47`/`#4a6b5e`) are deferred; this plan verifies severity-to-class mapping, which is a stable proxy for the CSS custom properties defined in `specs/features/08-board-severity.md`. A future revision could assert computed color values directly if class names become an unreliable proxy.
- The edit-bug modal's own severity dropdown color coding is covered in `specs/test-plans/edit-bug.md` (Scenario 1.2).

## Technical Information

### Seed / Fixture Guidance

Use `tests/seed.spec.ts` as the Playwright seed. Create bugs via `tests/support/board-fixtures.ts` (`createBug`) with unique titles per severity so each badge can be located unambiguously; clean up with `deleteBugIfExists`.

### Locator Guidance

Locate a bug's row via `tests/pages/board.page.ts`'s `rowByTitle`/`cellByTitle`, then find the severity badge within that row: `page.getByRole('table', { name: 'Bugs' }).getByText(title).locator('xpath=ancestor::tr').locator('.severity-badge')`, or more simply scope by row and assert `toHaveClass(/severity-badge-(high|mid|low)/)` and `toHaveAttribute('data-severity', 'HIGH' | 'MID' | 'LOW')` on the `<span class="severity-badge ...">` element in the Severity column cell.
