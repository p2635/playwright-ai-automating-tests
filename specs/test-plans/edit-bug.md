# BuggyBoard Edit Bug End-to-End Test Plan

- Version: 0.1
- Generated by Claude for Philip Wong on 24 September 2026
- Reviewed by: Philip Wong on 24 September 2026

## Feature Overview

BuggyBoard's Edit bug dialog lets an authenticated user open a bug from the board table and view or update its title, severity, owner, and description.

## Test Scenarios

### 1. Opening the edit-bug modal

#### 1.1. Opens the edit-bug modal from a board row with fields pre-populated

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title, severity, owner, and description.

**Steps:**

1. Click the board row for the known bug.

**Expected Results:**

1. A dialog titled "Edit bug (ID)" is visible, with the bug's actual ID interpolated. [09-AC1]
2. The dialog shows an ID field, a Title field, a Severity field, an Owner field, and a Description field. [09-AC1]
3. The dialog contains Save and Cancel buttons. [09-AC1]
4. The ID field displays the bug's ID and is read-only (disabled or `aria-readonly`). [09-AC2]
5. The Title, Severity, Owner, and Description fields are populated with the bug's existing values and are editable. [09-AC2]

#### 1.2. Severity dropdown uses the same color coding as the board

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with severity HIGH.

**Steps:**

1. Open the edit-bug modal for that bug.

**Expected Results:**

1. The Severity field is a dropdown offering HIGH, MID, and LOW options. [09-AC3]
2. The Severity dropdown carries a severity-specific class (e.g. `severity-select-high`) matching the selected value. [09-AC3]

### 2. Saving changes

#### 2.1. Saves an edited Title and reflects it on the board

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Title to a new unique value.
3. Click Save.

**Expected Results:**

1. The Save button becomes enabled once the title changes. [09-AC9]
2. The dialog is closed after saving. [09-AC5]
3. A board row shows the new title. [09-AC5]
4. No board row shows the original title. [09-AC5]

#### 2.2. Saves an edited Severity and reflects it on the board

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title and severity LOW.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Severity field to HIGH.
3. Click Save.

**Expected Results:**

1. The Save button becomes enabled once the severity changes. [09-AC9]
2. The dialog is closed after saving. [09-AC5]
3. The board row for that bug shows a HIGH severity badge (`severity-badge-high`). [09-AC5]

#### 2.3. Saves an edited Owner and reflects it on the board

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title and owner.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Owner field to a new value.
3. Click Save.

**Expected Results:**

1. The Save button becomes enabled once the owner changes. [09-AC9]
2. The dialog is closed after saving. [09-AC5]
3. The board row for that bug shows the new owner. [09-AC5]

#### 2.4. Saves an edited Description

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title and description.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Description field to a new value.
3. Click Save.

**Expected Results:**

1. The Save button becomes enabled once the description changes. [09-AC9]
2. The dialog is closed after saving. [09-AC5]
3. Reopening the edit-bug modal for that bug shows the new description value. [09-AC5]

#### 2.5. Saved changes persist after reload

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title and owner.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Owner field to a new value and click Save.
3. Reload the page.

**Expected Results:**

1. The board row for that bug still shows the updated owner after reload. [09-AC5]

#### 2.6. Save button is disabled with no changes

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists.

**Steps:**

1. Open the edit-bug modal for the bug.

**Expected Results:**

1. The Save button is disabled immediately after opening, before any field is modified. [09-AC10]

#### 2.7. Save button is disabled when a required field is cleared

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Clear the Title field.

**Expected Results:**

1. The Save button is disabled while the Title field is blank. [09-AC11]

### 3. Discarding changes

#### 3.1. Cancels without saving

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug.
2. Change the Title field to a different unique value.
3. Click Cancel.

**Expected Results:**

1. The changed title is visible in the field before cancelling. [plan-only]
2. The dialog is closed. [09-AC6]
3. The board row still shows the original title, not the changed one. [09-AC6]

#### 3.2. Closes with the X button without saving

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug and change the Title field.
2. Click the Close button in the upper-right corner.

**Expected Results:**

1. The dialog is closed. [09-AC7]
2. The board row still shows the original title. [09-AC7]

#### 3.3. Closes with Escape without saving

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists with a known unique title.

**Steps:**

1. Open the edit-bug modal for the bug and change the Title field.
2. Press Escape.

**Expected Results:**

1. The dialog is closed. [09-AC8]
2. The board row still shows the original title. [09-AC8]

#### 3.4. Keeps entered data when the backdrop is clicked

**Preconditions:**

1. Authenticate as `buggy` and open the board.
2. A bug exists.

**Steps:**

1. Open the edit-bug modal for the bug and change the Title and Description fields.
2. Click the dimmed backdrop outside the dialog panel.

**Expected Results:**

1. The entered values are visible in the dialog before clicking the backdrop. [plan-only]
2. The dialog remains open. [09-AC4]
3. The changed Title and Description values are preserved. [09-AC4]

## Out of Scope (deferred)

- Conflict detection when the same bug is edited by more than one user (last write wins), per `specs/features/09-edit-bug.md` Out of Scope.
- Editing the bug's state field is covered separately in `specs/test-plans/bug-status.md`.
- Per-field blank validation for Severity/Owner/Description individually (only Title is exercised as the representative blank-field case in 2.7); to be addressed in a future revision.
- Reverting Severity/Owner/Description on cancel/X/Escape (scenarios 3.1-3.3 only exercise Title): acceptable, since discard-on-close is implemented as a single `onClose` handler that simply drops all uncommitted field state regardless of which field changed — testing one field is representative of the same code path.
- Keyboard-only interaction (opening the edit modal via a focused board row and Enter/Space, operating modal controls via Tab/Enter) is not currently tested; not in scope for this round of coverage.

## Technical Information

### Seed / Fixture Guidance

Use `tests/seed.spec.ts` as the Playwright seed for every workflow. Create bugs via `tests/support/board-fixtures.ts` (`createBug`) with unique titles per test for traceability, and clean up with `deleteBugIfExists` where the test does not itself delete the bug.

### Locator Guidance

Reuse `tests/pages/board.page.ts` (`openBugByTitle`, `rowByTitle`) and `tests/pages/edit-bug-dialog.page.ts` (`dialog`, `cancelButton`, `saveButton`) as a starting point; extend the latter with labeled field locators: `dialog.getByLabel('ID')`, `getByLabel('Title')`, `getByLabel('Severity')`, `getByLabel('Owner')`, `getByLabel('Description')`, and `getByRole('button', { name: 'Close' })` for the X button. The severity dropdown's color class can be asserted via `toHaveClass(/severity-select-high/)` (or `-mid`/`-low`).

### Testability

- Scenario 3.4 ("Keeps entered data when the backdrop is clicked") targets an unlabeled backdrop `<div>` wrapping the dialog, with no `data-testid` or other stable handle. During generation, click the backdrop container at an offset outside the dialog panel bounds (e.g. `page.locator('[role="dialog"]').click({ position: { x: 4, y: 4 } })` against the outer wrapper, verified against the actual DOM via `playwright-cli` snapshot) rather than guessing a selector up front. If this proves unreliable, flag it back here rather than adding a `data-testid` to app code without confirming with the team first.
