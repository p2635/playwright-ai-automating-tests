## Feature Overview

BuggyBoard's bug Edit modal includes a Delete button. Clicking it opens a confirmation modal; the bug is only removed once the user confirms in that modal. Cancelling the confirmation (via its Cancel button, its X, or Escape) keeps the bug and returns to the Edit modal.

## Test Scenarios

### 1. Delete bug workflow

#### 1.1. Edit modal shows a delete button

**Preconditions:**

1. Create an Open bug titled `Delete bug test scenario 1.1 <timestamp>` via the API.

**Steps:**

1. Open the board and click the newly created bug row (Preconditions 1) to open the Edit modal.

**Expected Results:**

1. The "Edit bug" dialog is visible. [12-AC1]
2. The dialog shows a "Delete" button. [12-AC1]
3. The dialog also shows "Cancel" and "Save" buttons. [12-AC1]

## Technical Information

### Seed / Fixture Guidance

Use `tests/seed.spec.ts` as the Playwright seed for every workflow. It authenticates as the `buggy` user and verifies navigation to `/board`.

Each scenario must create the bug(s) it deletes as part of its own setup, via the backend REST API (`POST http://localhost:3000/api/bugs`, matching the `BugFixture` shape and the `createBug`/`deleteBugIfExists` helpers in `tests/support/board-fixtures.ts`), so every test starts from a known, isolated bug rather than relying on pre-existing board data. Do not delete or reset unrelated bugs already on the board.

Give every created bug a descriptive, unique title that identifies the scenario and run, e.g. `Delete bug test scenario 1.2 <ISO timestamp>`, so a human reviewing a test report or the database can trace a leftover or failed-deletion row back to the exact scenario that created it.

### Locator Guidance

Prefer accessible Playwright locators: `getByRole('button', { name: 'Open' })` / `getByRole('button', { name: 'Closed' })` for the state filter, `getByRole('table', { name: 'Bugs' })` and row text for board identity, `getByRole('dialog', { name: /Edit bug/ })` for the Edit modal, and `getByRole('button', { name: 'Delete' })` / `'Cancel'` / `'Save'` within it. For the confirmation modal, use `getByRole('dialog', { name: /Delete bug/ })` and `getByRole('button', { name: 'Delete' })` / `'Cancel'` within it — scope these to the confirmation dialog locator to avoid ambiguity with the Edit modal's own buttons of the same name. Use `GET http://localhost:3000/api/bugs` to verify server-side state (existence, absence, and count) independent of the UI.
